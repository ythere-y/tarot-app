# 受控 LLM 塔罗解读设计

## 1. 目标

在现有单张塔罗抽牌体验中加入可直接使用的 AI 解读。用户只从“综合、感情、事业、财运、成长”五个固定主题中选择一个，不输入自由文本。系统以已抽中的牌、正逆位和本地标准牌义为事实边界，由 LLM 生成简短、温和、非确定性的中文反思文本。

该功能是娱乐性自我反思，不宣称预测真实未来，也不替代医疗、法律、财务或其他专业建议。

## 2. 范围

本期包含：

- 五个固定主题选择器；
- 抽牌揭示后的 AI 解读请求；
- Node.js 服务端代理和静态文件服务；
- OpenAI Responses API 集成；
- 结构化输出、输入和输出校验；
- 超时、限流、错误提示及本地牌义降级；
- 配置示例、运行文档和自动化测试。

本期不包含自由问题、多轮对话、账户、云端历史、付费、向量检索、多牌阵或个性画像。

## 3. 架构

浏览器只调用同源的 `POST /api/reading`，不接触 API Key。Node.js 服务读取 `OPENAI_API_KEY`，校验请求后调用 OpenAI Responses API。模型默认为 `gpt-5.4-nano`，可通过 `OPENAI_MODEL` 覆盖。

请求边界：

```json
{
  "topic": "career",
  "cardName": "The Fool",
  "orientation": "upright",
  "standardMeaning": "新的开始，自由，纯真。"
}
```

服务只接受枚举主题、枚举方向以及有严格长度上限的牌名和标准牌义。浏览器不可提交系统提示词或任意额外上下文。

响应边界：

```json
{
  "headline": "给新可能留出位置",
  "reading": "这张牌提醒你……",
  "action": "今天写下一项可以低成本尝试的行动。",
  "disclaimer": "内容仅供娱乐与自我反思。"
}
```

所有字段必需且有服务端长度限制。前端使用文本节点渲染，不把模型输出作为 HTML 注入。

## 4. 生成控制

服务端提示词固定并规定：

- 只能依据提供的牌、方向、主题和标准牌义；
- 使用“可能、提醒、可以考虑”等非确定性措辞；
- 不声称预知事实，不制造恐惧、诅咒或必然结果；
- 不提供诊断、治疗、法律结论、投资买卖或高风险决策指令；
- 财运主题仅能讨论预算、审慎和目标反思；
- 产出简体中文，不索取个人信息；
- 严格返回约定 JSON Schema。

服务端在返回浏览器前再次校验字段类型和长度。无效输出按失败处理，不直接透传原始模型文本。

## 5. 用户体验与数据流

1. 用户在抽牌前选择主题，默认“综合”。
2. 原有抽牌和正逆位判定保持不变。
3. 卡牌揭示后立即展示本地标准牌义，并出现“星语生成中”状态。
4. 前端向 `/api/reading` 发送一次请求，并锁定当前卡牌与主题，避免动画或重复手势触发多次调用。
5. 成功后展示标题、解读和一个低风险行动建议，并标注“AI 生成 · 仅供娱乐与自我反思”。
6. 失败、超时或未配置 Key 时保留标准牌义，显示“AI 解读暂不可用”，允许显式重试一次。
7. 新一轮抽牌会取消旧请求，迟到响应不得覆盖新卡牌结果。

## 6. 服务可靠性与安全

- API Key 只来自服务端环境变量，`.env` 被 Git 忽略，仓库只提供 `.env.example`。
- JSON 请求体设较小上限；拒绝未知字段、未知主题和超长文本。
- OpenAI 调用设置超时，客户端断开时中止上游请求。
- 对单个 IP 使用轻量内存限流；响应不暴露上游错误详情、提示词或密钥。
- 服务设置基本安全头，并仅提供项目目录内的静态文件，阻止目录穿越。
- 不保存请求、牌面结果或生成文本。
- 生成接口只接受 POST；其他方法返回明确错误。

## 7. 组件边界

- `server.mjs`：启动 HTTP 服务、提供静态资源、路由 API。
- `src/server/reading-service.mjs`：验证输入、构建固定提示、调用 OpenAI、验证输出。
- `src/server/rate-limit.mjs`：无持久化的单进程限流。
- `src/client/reading.js`：主题状态、请求取消、加载/成功/失败 UI；如维持单文件结构困难，可先以内嵌模块实现但保持相同接口。
- `index.html`：主题选择器和 AI 解读展示区域，继续负责现有 Three.js/MediaPipe 体验。

LLM 功能不修改随机抽牌、正逆位判定或手势状态规则。

## 8. 测试与验收

自动化测试覆盖：

- 五个主题和两种方向均可通过输入校验；
- 未知字段、未知枚举、空值和超长字段被拒绝；
- 提示词包含标准牌义和安全约束，不包含客户端可控指令；
- 合法结构化输出通过，无效或超长输出被拒绝；
- 缺少 API Key、上游超时、限流和上游错误返回稳定的安全错误；
- 静态服务阻止目录穿越；
- 前端重复揭牌不会产生重复请求，旧响应不会覆盖新结果；
- 无 API Key 时原有抽牌和标准牌义仍可用。

人工验收：配置 `OPENAI_API_KEY` 后运行单一启动命令，访问本地地址，选择任意主题完成抽牌，能看到与牌面和主题一致的受控中文解读；断开网络后仍能正常抽牌并看到固定牌义。

## 9. 配置和运行

仓库提供 `.env.example`：

```text
OPENAI_API_KEY=
OPENAI_MODEL=gpt-5.4-nano
PORT=8080
```

README 说明安装依赖、复制环境变量、启动和测试命令。服务启动时若未配置 Key，会明确提示 AI 功能处于降级状态，但仍启动静态应用。
