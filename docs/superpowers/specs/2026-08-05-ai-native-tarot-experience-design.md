# Ether Tarot AI 原生体验升级设计

## 1. 目标

将现有 Ether Tarot 重构版升级为一款具有实体抽牌手感、单手手势控制、运行时 LLM 个性化解读和明确安全边界的 AI 原生塔罗体验。

本次升级不改变以下核心原则：

- 抽牌、正逆位和牌序由确定性游戏核心控制。
- LLM 只能解释已锁定的结果，不能影响抽牌结果。
- 摄像头不可用时，鼠标、触摸和键盘仍能完成等价流程。
- 网络或 LLM 失败时，完整本地牌义仍然可用。
- 涉及高风险决策或预测的问题在抽牌前被阻止。

## 2. 产品定位

产品定位为：

> 一款由手势驱动、在运行时通过受约束 LLM 生成个性化解读的沉浸式塔罗体验。

产品不是确定性预言工具，也不替代医疗、法律、财务或其他专业意见。塔罗牌用于娱乐、自我反思和叙事体验。

## 3. 架构方向

采用模块化 TypeScript 与按功能组织的架构。避免将完整六边形架构机械套入单一前端应用，也避免继续扩展大型入口文件。

### 3.1 依赖规则

- `features/draw`、`tarot` 和安全策略不得依赖 Three.js、MediaPipe、DOM 或 LLM SDK。
- Three.js 场景消费状态和动画指令，不决定业务结果。
- MediaPipe、鼠标、触摸和键盘统一输出语义事件。
- LLM Provider 只能读取已锁定的抽牌事实和经过筛选的上下文。
- 外部模型、存储和资源通过小型接口隔离，只有存在真实替换需求时才抽象。

## 4. 状态机

统一状态机覆盖开场、问题安全检查、洗牌、切牌、浏览、抽取、揭示和归档。

```text
BOOT
  ↓
INTRO
  ↓
QUESTION_ENTRY
  ↓
SAFETY_CHECK
  ├─ BLOCKED
  ├─ REFRAME_REQUIRED
  └─ SHUFFLE_READY
       ↓
SHUFFLING
       ↓
CUT_READY
       ↓
CUTTING
       ↓
FORMING_DECK
       ↓
BROWSING
       ↓ PINCH 命中
HOLDING
  ├─ 无效释放 → BROWSING
  └─ 中央释放 → PLACED
                    ↓ FIST 停留确认
                 REVEALING
                    ↓
                  READING
                    ↓ 完成阅读
                 ARCHIVING
                    ↓
            BROWSING / COMPLETE
```

每个状态只响应明确允许的语义事件。动画期间忽略重复输入。状态转换不使用散落的 `setTimeout`。

## 5. 牌盒开场

采用已批准的方案 A“机械拆解仪式”。

### 5.1 分镜

总时长约 4.2 秒：

1. `0–0.5s`：黑场与星尘中出现闭合牌盒。
2. `0.5–1.4s`：盒盖、金属边框和侧板沿不同轴向错层拆解。
3. `1.1–2.0s`：内托上升，中央符号和边缘金线点亮。
4. `1.7–3.7s`：78 张牌分批沿螺旋轨迹飞出。
5. `3.2–4.2s`：卡牌减速并聚合为待洗牌牌堆。

开场不请求摄像头。动画结束后，用户主动启用手势。

### 5.2 技术边界

```text
features/intro/
├── intro-sequence.ts
├── intro-timeline.ts
├── tarot-box-view.ts
├── card-flight-planner.ts
└── tests/
```

- `IntroSequence` 暴露 `play()`、`skip()` 和 `dispose()`。
- anime.js 仅作为时间线适配器，不拥有应用状态。
- 飞出阶段仅使用统一牌背，不预载 78 张高清正面。
- 同一批卡牌对象交给后续牌堆和牌列，不重复创建。
- `prefers-reduced-motion` 下使用约 500ms 的最终布局淡入。
- 约 0.6 秒后显示跳过按钮；跳过动画在约 180ms 内收敛到最终状态。

## 6. 洗牌与切牌

参考 Digital Tarot 的实体牌组手感，但使用适合单摄像头识别的混合式交互。

### 6.1 随机牌序

- 使用 Fisher–Yates 洗牌。
- 随机源优先使用 `crypto.getRandomValues()`。
- 洗牌动画与底层牌序更新具有明确的单一提交点。
- 同一会话中的牌序保持稳定。
- 已抽牌从剩余牌库移除，不再出现。

### 6.2 洗牌交互

- OPEN 手掌完成一次明显的水平扫动，计为一次洗牌输入。
- 每次有效扫动触发牌堆分裂、交错和合并动画。
- 完成 2–3 次有效扫动后，系统完成最终洗牌。
- UI 显示“洗牌 1/3”等进度。
- 鼠标和触摸通过水平拖动完成等价操作。
- 提供“自动洗牌”按钮作为无障碍和稳定性降级。

### 6.3 切牌交互

- 洗牌后形成左、中、右三叠。
- OPEN 左右移动高亮牌堆。
- PINCH 确认选择。
- 系统自动改变牌堆顺序并重新合并。
- 鼠标点击、触摸和键盘焦点选择提供等价操作。

## 7. 双向循环牌列

底层保留完整剩余牌库，桌面只展示中心附近 7 张，移动端展示 5 张。

```text
visibleIndex = modulo(currentIndex + offset, remainingCards.length)
```

### 7.1 行为

- 第 78 张继续向右时无缝回到第 1 张。
- 第 1 张继续向左时无缝进入第 78 张。
- 抽牌后，只在剩余牌库中继续双向循环。
- 屏幕外卡牌不创建独立可见对象；复用离开视口的 CardView。
- 中央卡牌为主要候选，相邻卡牌按距离缩小并降低亮度。
- 不按时间自动旋转。

### 7.2 OPEN 旋转控制

- 只有 `BROWSING` 状态下确认的 OPEN 手势可以控制牌列。
- 屏幕中央约 12% 为死区。
- 手掌离中心越远，牌列速度越快。
- 回到中心后保留短暂惯性并平滑停止。
- POINT 可立即停止惯性并高亮指向的卡牌。
- PINCH、HOLDING、PLACED、REVEALING、READING 和 ARCHIVING 状态立即锁定牌列。

鼠标支持拖动、滚轮和方向键；触摸支持水平滑动。

## 8. 抓取、揭牌与归档

### 8.1 PINCH 抓取

- PINCH 必须稳定数帧且射线命中卡牌。
- 抓取后卡牌带轻微平滑延迟跟随指针，表现重量。
- 其余卡牌向两侧外移、降低到约 20% 亮度并停止循环。
- 中央显示明确放置区。
- 有效区释放进入 `PLACED`；无效区释放返回原位。

### 8.2 FIST 确认

- FIST 持续约 500ms 后确认。
- 显示圆环进度。
- 完成时原子性锁定卡牌 ID、正逆位和时间。
- 正逆位在锁定时生成，不由 LLM 决定。

### 8.3 揭示

- 卡牌沿 Y 轴翻面。
- 逆位额外绕 Z 轴旋转 180°。
- 揭示牌位于独立中央舞台和渲染层。
- 两侧牌列不得遮挡揭示牌。
- 牌名、正逆位和关键词优先出现，详细牌义随后展开。

### 8.4 归档

- 完成阅读后，牌面几何采样为灰烬粒子。
- 粒子具有随机大小、寿命、透明衰减、上飘和轻微湍流。
- 归档完成后才减少余牌并写入历史。
- 历史缩略图保留真实牌面和逆位旋转。

## 9. 界面设计

界面参考用户提供的交互截图，但不复制短视频平台外框。

### 9.1 浏览状态

- 黑色全屏舞台。
- 顶部左侧为手势与鼠标模式控制。
- 顶部中央显示当前手势和下一步提示。
- 顶部右侧显示余牌数量和重置入口。
- 中部横向展示 5–7 张牌。
- 手势指针使用高对比圆环。
- 左下显示阅读历史缩略图。
- 详细牌义不常驻占用舞台。

### 9.2 阅读状态

- 中央显示放大的牌面。
- 牌名、英文名、正逆位和关键词位于牌下。
- 综合、爱情、事业、财富和成长使用底部抽屉或标签切换。
- AI 内容流式进入，不改变已显示的本地核心牌义。
- 支持用户问题、个人笔记和保存到阅读日记。

## 10. 牌组资源

采用可替换牌组包：

```text
assets/decks/rws-classic/
├── deck.json
├── back.webp
└── cards/
    ├── 00-the-fool.webp
    └── ...
```

```ts
interface TarotDeck {
  id: string;
  name: string;
  cardBack: string;
  cards: Record<string, string>;
  license: DeckLicense;

```

第一始牌组使用项目已有的经典 RWS 图片，统一裁切、颜色空间和 WebP 压缩，使比例和表现接近 Digital Tarot。

不得：

- 热链 Digital Tarot 的牌面。
- 在无授权情况下复制其特有裁切、调色、牌背或品牌素材。
- 将来源与许可不明的素材描述为可自由发布。

若用户提供已获授权的同款素材，可作为新的 Deck Pack 接入。

## 11. AI 原生解读

采用“确定性核心 + 生成式解释层”。

### 11.1 AI 可以生成

- 与玩家问题相关的个性化解读。
- 多张牌之间的关系。
- 正逆位在当前语境中的侧重点。
- 受控行动建议和反思问题。
- 阅读日记标题与摘要。
- 经用户同意后的跨会话主题总结。

### 11.2 AI 不得控制

- 抽到哪张牌。
- 正位或逆位。
- 洗牌和切牌结果。
- 状态机转换。
- 历史事实。
- 手势是否成立。

### 11.3 Provider

```text
InterpretationProvider
├── LocalInterpretationProvider
├── DeepSeekInterpretationProvider
└── HybridInterpretationProvider
```

浏览器只请求自己的 `/api/interpret`。DeepSeek API Key 仅保存在服务端环境变量中。

```env
DEEPSEEK_API_KEY=
DEEPSEEK_BASE_URL=
DEEPSEEK_MODEL=
```

模型名称、服务地址和 API Schema 通过配置提供，不在领域层写死。

## 12. 受控生成

LLM 是受约束文本合成器，而不是自由占卜者。

```text
标准牌义
+ 正逆位
+ 牌阵位置
+ 玩家问题
+ 时间上下文
+ 本地计算的月相和当前太阳星座
+ 白名单扰动变量
  ↓
DeepSeek 结构化生成
```

### 12.1 上下文

第一版只使用：

- 本地时间与时区。
- 月相和照明比例。
- 当前太阳星座。
- 时段。
- 季节。
- 用户选择的主题和语气。

不加入上升星座、行星宫位和完整出生星盘。

### 12.2 受控扰动

```ts
type ReadingFocus =
  | "opportunity"
  | "risk"
  | "relationship"
  | "inner-conflict"
  | "action"
  | "reflection";

type ReadingTone =
  | "gentle"
  | "grounded"
  | "mystical"
  | "direct";
```

扰动来自白名单，并使用会话种子保证同一阅读可重放：

```text
seed = hash(sessionId + cardId + orientation + drawnAt)
```

### 12.3 输出结构

```ts
interface AiReading {
  headline: string;
  summary: string;
  interpretation: string;
  themes: string[];
  guidance: string[];
  reflectionQuestions: string[];
  safetyNote?: string;
}
```

本地固定牌义永远可见。AI 内容必须通过 JSON Schema 和语义边界校验。失败时最多重试一次，之后回退本地牌义。

## 13. 安全边界

安全门位于洗牌之前。

```text
用户问题
  ↓
本地规则初筛
  ↓
独立安全分类器
  ├─ allow
  ├─ reframe
  ├─ block
  └─ urgent
```

### 13.1 阻止类别

- 投资和具体财务决策。
- 医疗诊断、治疗选择和疾病预测。
- 法律结果和法律行动建议。
- 死亡时间、灾难或确定性伤害预测。
- 自伤、他伤和即时人身危险。
- 犯罪实施或规避。
- 替他人作重大医疗、财务或法律决定。

阻止时：

- 不洗牌。
- 不抽牌。
- 不请求解读模型。
- 不保存为正常阅读。
- 展示中性解释和现实帮助方向。

自伤、他伤或即时危险场景停止塔罗体验，转向当地准确的紧急支持信息。

### 13.2 改写

敏感但可转为自我反思的问题先进入 `reframe`。系统建议安全改写，用户必须明确确认并重新触发安全分类，不能自动开始抽牌。

### 13.3 双层校验

- 输入层：本地规则与独立安全分类器。
- 输出层：检查诊断、投资指令、法律结论、死亡预测和确定性承诺。
- 分类超时、格式错误或冲突时采用更严格结果。

默认不保存敏感问题原文。安全日志只保留分类结果、类别、规则版本、时间和是否改写。

## 14. 日记与未来扩展

第一版日记使用本地存储：

- 日期与时间。
- 用户问题。
- 牌阵。
- 牌面事实和正逆位。
- 标准牌义。
- AI 解读。
- 用户笔记。

未来可以增加：

- 多牌阵与自定义牌阵。
- 加密云端同步。
- 用户主动授权的跨会话主题分析。
- 多套牌组。
- 实体牌阵摄像头识别。
- AR 放置。
- 有限的结构化追问。

这些不属于本次第一阶段实现。

## 15. 错误处理

- 摄像头失败：自动切换指针模式并显示重试。
- WebGL 失败：进入完整可用的 2D 模式。
- 牌面加载失败：使用同尺寸本地占位，不写入未揭示历史。
- LLM 超时或失败：显示本地牌义。
- LLM 输出不合格：重试一次后回退。
- 安全分类失败：阻止抽牌并允许重试。
- 页面隐藏：暂停推理和动画，清除手势停留进度。
- 页面销毁：取消请求、停止媒体轨道并释放 Three.js 资源。

## 16. 测试策略

### 16.1 单元测试

- Fisher–Yates 牌序与注入随机源。
- 三叠切牌顺序。
- 双向循环索引。
- OPEN 死区、速度和惯性。
- 状态机合法与非法转换。
- 正逆位锁定。
- 受控扰动可重放。
- 月相和时间上下文。
- 安全规则与输出校验。

### 16.2 集成测试

- 开场跳过与正常完成。
- 洗牌、切牌、循环、抓牌、揭示、归档。
- 手势、鼠标、触摸和键盘等价事件。
- DeepSeek 成功、超时、错误格式与本地回退。
- 受限问题不进入洗牌和解读。

### 16.3 浏览器验收

- 真实桌面浏览器和摄像头。
- 移动端触摸。
- 摄像头拒绝。
- 慢速牌面和慢速 LLM。
- 减少动态效果。
- WebGL 不可用。
- 双向连续循环无跳变。
- 揭示牌不被牌列遮挡。

## 17. 第一阶段交付范围

本轮实现：

- 机械牌盒开场。
- 混合式洗牌和三叠切牌。
- 5–7 张虚拟化双向循环牌列。
- OPEN/PINCH/FIST 和可选 POINT。
- 中央揭示舞台与灰烬归档。
- 经典 RWS 本地牌组包。
- 本地问题安全门。
- DeepSeek Provider 接口、服务端代理和本地回退。
- 单牌受控 AI 解读。
- 本地阅读日记。

暂不实现：

- 多牌阵。
- 无限 AI 聊天。
- 长期云端记忆。
- 实体牌识别。
- AR。
- 出生星盘。
- 未获授权的 Digital Tarot 资源复制。
