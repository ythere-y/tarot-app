# 小阿卡那四元素特效设计

## 1. 目标与范围

为韦特体系的 56 张小阿卡那增加与花色对应的四元素 3D 特效：权杖为火、圣杯为水、宝剑为风、星币为土。特效服务于抽牌仪式感和牌义感知，不改变随机抽牌、正逆位判定、手势识别、射线检测或 AI 解读输入。

本期仅设计与实现小阿卡那元素特效。22 张大阿卡那不复用小牌元素特效。

## 2. 搁置需求：大阿卡那逐牌专属特效

后续为 22 张大阿卡那逐牌设计独立特效，而不是统一星云或临时映射到四元素。例如魔术师可使用四元素汇聚，女祭司可使用月相与水幕，高塔可使用闪电和碎裂，太阳可使用日冕与光束。

该需求当前明确搁置：

- 不进入本期代码、测试和验收范围；
- 本期控制器遇到 `type: "major"` 时返回空效果；
- 当前架构必须允许未来注册 22 个独立的大牌效果，而不修改抽牌状态机或小牌映射；
- 后续需单独完成大阿卡那视觉语言、性能预算、无障碍降级和逐牌验收规格。

## 3. 依据与元素语义

采用 Rider–Waite–Smith 常用四元素对应：

| 花色 | 元素 | 核心语义 | 视觉动词 |
| --- | --- | --- | --- |
| Wands / 权杖 | Fire / 火 | 意志、行动、创造、热情 | 点燃、上升、爆发、跳动 |
| Cups / 圣杯 | Water / 水 | 情感、关系、直觉、潜意识 | 流动、环绕、涟漪、凝聚 |
| Swords / 宝剑 | Air / 风 | 思想、判断、冲突、真相 | 掠过、切开、旋转、散射 |
| Pentacles / 星币 | Earth / 土 | 现实、财富、身体、工作、稳定 | 沉降、聚合、生长、成形 |

牌义文案仍由本地标准牌义和受控 LLM 负责。特效只表达花色元素与正逆位能量方向，不推导新的占卜结论。

## 4. 生命周期

采用三阶段体验：

1. `prepare(card, orientation)`：卡牌从牌堆抽出时预热。使用低强度元素光、少量粒子和轻微运动，提示花色但不遮挡牌面。
2. `reveal()`：确认揭牌时短暂爆发。增强粒子密度、速度、光环或法阵，并在约 600–1000 ms 内回落。
3. `settle()`：阅读阶段进入低强度循环。粒子避开牌面主体，仅在边缘和卡牌周围持续运动。

控制器每帧接收 `update(deltaTime)`。卡牌销毁、开始下一轮、切换页面或 WebGL 上下文丢失时调用 `dispose()`，停止动画并释放几何体、材质、纹理与监听器。

同一时间最多存在一个活动元素特效实例。新的 `prepare` 必须先清理旧实例。迟到动画不得操作已销毁卡牌。

## 5. 正位与逆位

正位统一表达为能量向外、上升和稳定展开。逆位保持原元素，但表达能量受阻、内化或紊乱：

| 元素 | 正位 | 逆位 |
| --- | --- | --- |
| 火 | 火星上升、火焰外展、稳定跳动 | 火焰内卷、火星下坠、偶发熄灭 |
| 水 | 水滴环绕、波纹向外、柔和上浮 | 水流倒悬、波纹向内收缩、局部回卷 |
| 风 | 羽流流畅旋转、刃光沿外侧掠过 | 风流紊乱、刃光断续、反向旋转 |
| 土 | 金绿尘埃沉降、碎片聚合、法阵生长 | 土尘松散、法阵不稳定、碎片轻微上浮 |

逆位不更换元素、不改变牌面方向、不增加负面恐吓视觉。

## 6. 四元素视觉规格

### 6.1 权杖·火

- 色板：核心淡金 `#FFE29A`、主焰橙 `#FF8A2A`、外焰红 `#D9381E`。
- 预热：牌边稀疏余烬向上漂浮，底部有轻微橙光呼吸。
- 爆发：边缘火舌和火星向外喷发；高性能档可加入局部热浪扭曲。
- 循环：少量余烬沿牌边上升，不覆盖人物和标题区域。

### 6.2 圣杯·水

- 色板：高光青白 `#D9FAFF`、主水蓝 `#42C8E8`、深水蓝 `#2464C7`。
- 预热：牌边出现细水线和少量悬浮水珠。
- 爆发：同心涟漪扩散，水滴沿弧线绕牌运动；高性能档可加入轻量折射。
- 循环：柔和波纹与薄雾缓慢流动，避免整面蓝色覆盖。

### 6.3 宝剑·风

- 色板：银白 `#F3F7FF`、冷青 `#9EDCFF`、淡紫灰 `#A8A3C7`。
- 预热：细羽流沿卡牌长边移动，偶发短促银光。
- 爆发：两至三道弧形风刃从牌外掠过，配合细小气流粒子。
- 循环：低透明度螺旋气流绕牌旋转，不使用频繁屏幕闪烁。

### 6.4 星币·土

- 色板：金色 `#D9A83E`、苔绿 `#6F9B52`、土褐 `#76513A`。
- 预热：金绿微尘下沉，在牌底形成稀疏几何节点。
- 爆发：五芒星或同心几何法阵由内向外成形，碎石/金币微粒聚合。
- 循环：尘埃缓慢沉降，法阵以低透明度呼吸；不持续遮挡牌面。

## 7. 架构与接口

使用 GPU 友好的 `ShaderMaterial` 与 `InstancedMesh` 或等价的单批次绘制实现。统一入口：

```ts
type MinorSuit = "Wands" | "Cups" | "Swords" | "Pentacles";
type Orientation = "upright" | "reversed";
type EffectPhase = "idle" | "prepared" | "revealing" | "settled" | "disposed";

interface MinorArcanaEffectController {
  prepare(card: TarotCard, orientation: Orientation, anchor: THREE.Object3D): void;
  reveal(): void;
  settle(): void;
  update(deltaTime: number): void;
  dispose(): void;
}
```

建议模块边界：

- `minor-effect-map`：只负责验证牌型并把花色映射到元素；大阿卡那返回 `null`。
- `effect-profile`：生成元素、方向、生命周期和性能档位对应的纯数据参数。
- `minor-effect-controller`：管理单实例生命周期、锚点跟随和清理。
- `element-renderer`：把 profile 转换为批次粒子、光环和可选高级效果。

映射和 profile 为纯函数，可在 Node 环境测试。Three.js 资源创建通过小型适配器隔离，测试可验证创建与释放次数。

## 8. 自动性能分级

运行时计算一次性能档位，并监听用户动态偏好变化：

| 档位 | 条件 | 粒子上限 | 高级效果 |
| --- | --- | ---: | --- |
| standard | 桌面设备、WebGL 能力正常、未减少动态 | 800 | 热浪、折射、完整法阵可启用 |
| low | 移动设备、低硬件并发或低渲染能力 | 250 | 关闭热浪与折射，简化几何 |
| reduced | `prefers-reduced-motion: reduce` | 80 | 仅短淡入、元素色光环和一次低速扩散 |

规则：

- 粒子上限是单活动特效的总量，不按子效果重复计算；
- 页面隐藏时暂停更新，恢复时不补算累计时间；
- `deltaTime` 设上限，避免后台恢复时粒子跃迁；
- 高级效果失败时自动降级，不阻断抽牌；
- 无 WebGL 特效能力时返回空效果，卡牌与解读仍完整可用。

## 9. 校验规则

构建或测试阶段必须验证：

- 小阿卡那恰好 56 张，四花色各 14 张；
- 每张小牌只有一个受支持的 `suit`；
- 映射固定为 Wands→fire、Cups→water、Swords→air、Pentacles→earth；
- 22 张大阿卡那和未知牌型均不产生小牌特效；
- 正逆位返回同一元素，只改变方向 profile；
- 所有 profile 的颜色、速度、生命周期、粒子数和透明度均在有限范围内；
- reduced/low/standard 粒子数不超过 80/250/800；
- 特效不得写入抽牌结果、牌库、手势或射线状态。

## 10. 测试矩阵

### 数据与映射测试

- 枚举 56 张小牌，断言元素映射完整且唯一；
- 断言每个花色 14 张、每个等级在每花色中恰好一次；
- 枚举 22 张大牌，断言映射为 `null`；
- 未知花色、缺失类型和非法方向返回明确校验错误。

### Profile 测试

- 四元素 × 两个方向 × 三个性能档，共 24 组 profile；
- 正逆位元素和色板一致，速度方向、旋转、扩散模式按规格不同；
- 三档粒子上限、爆发时长和高级效果开关符合表格；
- 数值全部有限，透明度在 0–1，生命周期为正数。

### 生命周期测试

- 初始为 `idle`；仅允许 `prepare → reveal → settle → dispose`；
- 重复 `reveal`、迟到 `settle` 和 disposed 后 `update` 不产生资源或副作用；
- 新卡 `prepare` 先释放旧实例；
- 每帧只更新当前活动实例；
- 页面隐藏暂停，恢复不跳帧；
- dispose 对所有几何体、材质和纹理恰好执行一次。

### 集成与回归测试

- 抽出小牌触发预热，确认揭牌触发爆发，阅读阶段转入循环；
- 抽出大牌不创建小牌特效；
- 正逆位卡牌视觉方向保持现有行为；
- 手势、鼠标、抽牌数量、历史记录和 AI 请求体不因特效改变；
- 关闭特效或 WebGL 降级时仍能完成完整抽牌流程；
- 连续抽牌后场景对象数和 GPU 资源计数回到稳定基线。

## 11. 验收标准

- 四种花色在预热阶段即可通过颜色和运动被区分；
- 揭牌爆发在 1 秒内完成并平滑转入低强度循环；
- 粒子和光环不遮挡牌名、核心人物或 AI 解读；
- 逆位显著不同但不使用恐吓、故障式频闪；
- 标准桌面保持流畅，低性能和减少动态模式按预算降级；
- 反复抽牌无持续增长的场景对象、监听器或 GPU 资源；
- 大阿卡那保持无小牌元素特效，为后续逐牌专属设计留出边界。
