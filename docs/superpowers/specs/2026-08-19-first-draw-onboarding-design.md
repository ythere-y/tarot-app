# 首次抽牌新手引导设计

## 目标

让从未接触过塔罗或本项目的用户，在不阅读外部说明的情况下完成第一次完整体验：选择输入方式、选择解读主题、抓取并揭示一张牌、理解结果区域。首次完成后不再强制打断，但始终可以从控制台重新打开帮助。

## 范围

本次只改善首次抽牌和操作帮助，不改变抽牌随机规则、正逆位概率、牌义数据、AI 解读接口、Three.js 牌桌表现或手势识别算法。

## 核心体验

### 首次入口

首次访问时，在牌桌上方显示沉浸式入口面板。用户必须先选择一种输入方式：

- 手势体验：说明摄像头只在浏览器内用于手部识别；仅在用户主动选择后启动或继续摄像头权限流程。
- 鼠标体验：无需摄像头，直接使用移动、按住和松开完成抽牌。

随后选择综合、感情、事业、财运或成长主题。入口面板明确说明主题只影响抽牌后的解读方向。确认后进入牌桌。

### 场景内实时引导

牌桌中央附近显示紧凑的引导卡，保留足够空间观察牌堆。引导由真实交互状态推进，而不是按固定计时播放。

手势模式步骤：

1. 让摄像头看见手。
2. 张开手并将光标移到牌堆。
3. 捏合拇指和食指抓牌。
4. 握拳揭示牌面。

鼠标模式步骤：

1. 将光标移到牌堆。
2. 按住鼠标抓牌。
3. 松开鼠标揭示牌面。

引导卡显示当前步骤、总步骤、明确动词和与当前模式对应的动作。用户可以跳过引导；跳过只关闭提示，不会阻止正常抽牌。

### 首次结果说明

首张牌揭示后，引导说明：

- 正位或逆位代表本次牌面方向。
- 固定牌义来自本地牌义数据，始终可用。
- “星语”是依据已选主题生成的 AI 解读，仅供娱乐与自我反思。

用户确认“知道了”后，首次教学记为完成。之后页面不再自动显示入口面板。

### 常驻帮助

神谕控制台增加“操作帮助”按钮。它根据当前输入模式重播对应的场景内步骤，但不重新展示主题选择，也不清除当前抽牌记录。模式切换后，帮助内容立即切换为新模式的操作说明。

## 组件与职责

新增独立的客户端 onboarding 控制器，负责：

- 保存首次入口、操作步骤和结果说明的有限状态。
- 渲染或更新入口面板、引导卡、进度和帮助按钮状态。
- 通过回调请求切换模式或选择主题。
- 接收现有抽牌逻辑发出的语义事件。
- 使用 `localStorage` 记录是否完成首次教学，并在存储不可用时安全退化为本次会话状态。

现有 `index.html` 负责提供引导 DOM、样式以及与 Three.js 交互点的连接。现有抽牌逻辑只需在关键位置通知控制器，不把教学判断塞进渲染循环。

## 状态与事件

引导状态为：

`welcome -> topic -> locate-input -> target-deck -> grab -> reveal -> result-explainer -> complete`

鼠标模式跳过 `locate-input`。关键事件包括：

- `mode-selected`
- `topic-selected`
- `hand-visible`
- `deck-targeted`
- `card-grabbed`
- `card-revealed`
- `result-explainer-dismissed`

控制器忽略顺序不匹配和重复事件，避免手势每帧回调导致步骤跳跃。帮助重播从当前模式的第一个操作步骤开始，不修改“首次教学已完成”标记。

## 异常与恢复

- 摄像头拒绝、启动失败或不可用：入口或引导卡显示具体失败状态，并提供“一键改用鼠标”；不再固定等待两秒后才恢复。
- 长时间未检测到手：保持当前步骤，显示“将整只手放入画面”的可执行提示，并提供切换鼠标入口。
- 用户中途切换模式：保留已选主题，将教学重置到新模式的第一个操作步骤。
- `localStorage` 读写失败：不影响抽牌，只在当前页面生命周期内记录进度。
- AI 解读失败：首次结果说明仍可完成，并强调固定牌义仍然可用。

## 响应式与无障碍

- 引导在桌面和移动端都可见，不复用当前会在小屏隐藏的 `.gesture-guide`。
- 入口面板和结果说明使用可聚焦的对话区域，打开时将焦点移入，关闭后归还到触发按钮。
- 支持键盘确认、Escape 跳过非强制教学、清晰的焦点样式和 `aria-live` 阶段提示。
- 遵循 `prefers-reduced-motion`，教学状态变化不依赖动画传达。
- 移动端仍显示完整引导，但本次不新增触控拖牌算法，界面不能承诺尚不存在的触控能力；支持触控将作为独立后续改进。

## 验收标准

1. 新用户首次进入能先选手势或鼠标，再选解读主题。
2. 选择手势前不主动请求摄像头权限。
3. 两种输入模式都有由真实操作驱动的逐步提示。
4. 摄像头失败时可立即改用鼠标并继续同一次教学。
5. 完成首抽后能看到正逆位、固定牌义和 AI 星语的简短说明。
6. 完成标记持久化后，刷新页面不再强制弹出首次入口。
7. 常驻“操作帮助”可以随时重播当前模式的操作步骤。
8. 引导在窄屏、键盘操作和减少动态效果设置下仍然可用。
9. 原有抽牌、历史记录、主题选择、AI 重试和元素特效继续工作。

## 测试策略

- 为 onboarding 控制器编写单元测试，覆盖首次状态、模式分支、事件顺序、跳过、重播和存储异常。
- 扩展页面烟雾测试，检查入口、帮助按钮、无障碍属性和控制器接线存在。
- 为手势不可用与改用鼠标路径增加行为测试。
- 运行完整 `npm test`，并以桌面和窄屏浏览器实际完成一次鼠标教学流程；手势路径至少验证权限触发时机、检测反馈与模式降级。
