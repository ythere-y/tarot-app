# Ether Tarot 初版体验恢复设计

## 目标

在保留当前 Vite、TypeScript、测试、本地资源和稳定性修复的前提下，将产品体验恢复为最初版本的直接交互方式：牌阵默认静止，用户张开手掌并左右移动时才驱动牌阵旋转；捏合抓牌，握拳确认，确认后以粒子灰烬归档并继续下一次抽牌。

本次工作是体验层恢复，不是将仓库强制回退到旧提交，也不是重新使用难以维护的单文件 HTML。

## 体验原则

- 用户动作是动画的原因；没有手势或指针输入时，牌阵不自行移动。
- 一次交互只需要理解三个核心手势：张开、捏合、握拳。
- 抽牌结果在确认前可移动，确认后立即锁定，避免重复抽取。
- 摄像头不可用时仍可通过鼠标或触摸完成等价流程。
- 初版的直接感优先于新版的仪式步骤和复杂视觉编排。

## 恢复范围

### 牌阵旋转

- 初始进入抽牌阶段时，牌阵保持静止。
- 当前阶段为待抽牌或浏览牌阵，并且稳定手势为 `OPEN` 时，手掌水平位置用于控制牌阵旋转。
- 手掌向左移动，牌阵向左旋转；手掌向右移动，牌阵向右旋转。
- 手掌停止后，牌阵立即停止，不保留惯性。
- 手势变为 `PINCH`、`FIST`、`UNKNOWN` 或 `LOST` 时，牌阵停止旋转。
- 垂直移动不控制牌阵旋转，仍可用于后续抓牌定位。
- 为避免抖动，水平输入经过现有指针平滑，并设置中心死区和最大转速。

### 抽牌流程

```text
进入牌阵
  → OPEN 左右浏览
  → PINCH 命中卡牌并抓取
  → 手掌移动带动卡牌到镜头前
  → FIST 确认并锁定牌面与正逆位
  → 显示牌名和对应牌义
  → 卡牌化为粒子并写入历史
  → 返回静止牌阵，等待下一次抽牌
```

- 保留 78 张不放回抽取。
- 保留每次抽牌独立生成正位或逆位。
- 保留正逆位对应牌义。
- 保留确认后的粒子灰烬效果。
- 保留历史记录、余牌数和下一次抽牌。
- 移除牌阵的时间驱动自动旋转。
- 不要求用户通过新版额外仪式动作才能开始浏览。

### 鼠标与触摸

- 鼠标或触摸水平移动仅在牌阵浏览状态控制旋转。
- 按下卡牌开始抓取，拖动卡牌，释放后完成与手势确认等价的操作。
- 摄像头权限失败、设备缺失或模型失败时自动切换到指针模式。
- 保留手势/鼠标切换入口。

### 界面

- 恢复初版的直接控制结构：输入模式、连接状态、当前手势、剩余卡牌、中央结果和历史记录。
- 界面以中文为主，英文牌名可作为辅助信息。
- 保留当前可访问按钮、键盘操作、错误提示和二维降级能力。
- 减少新版仪式化说明、复杂阶段提示和不必要的自动动画。
- 不移除摄像头重试、减少动态效果和 WebGL 失败回退。

## 技术设计

### 旋转状态

Three.js 场景新增显式 `carouselPhase`，表示牌阵当前角度。布局函数不再根据墙钟时间计算相位，而是接收该显式相位。

应用层只在以下条件同时成立时更新相位：

- 输入模式为手势；
- 稳定手势为 `OPEN`；
- 抽牌阶段允许浏览；
- 手掌水平位置超出中心死区。

每帧旋转增量由水平偏移和帧间隔计算，并限制最大帧间隔，避免标签页恢复后瞬间跳转。场景暂停、手部丢失或输入模式切换时不累积旋转。

指针模式使用同一旋转接口，保证手势、鼠标和触摸不会分别实现不同的牌阵规则。

### 接口边界

场景层提供：

```ts
setCarouselInput(horizontal: number): void
```

其中 `horizontal` 取值范围为 `-1` 到 `1`：

- `-1`：最大速度向左；
- `0`：停止；
- `1`：最大速度向右。

场景动画循环负责根据输入和帧间隔更新 `carouselPhase`。卡牌布局只消费相位，不读取手势、摄像头或应用状态。

### 保留模块

- `src/tarot/`：完整牌组与牌义。
- `src/draw/`：不放回抽牌和状态锁定。
- `src/gestures/`：MediaPipe、手势稳定和指针平滑。
- `src/interpretation/`：本地牌义 Provider。
- `src/scene/`：Three.js、纹理、粒子和降级。
- `src/ui/`：中文界面、无障碍和输入回退。

## 异常与边界

- 未检测到手：旋转输入立即归零。
- 识别到不稳定手势：旋转输入归零。
- `PINCH` 开始抓牌：冻结牌阵角度，避免目标从手下滑走。
- 握拳确认和粒子归档期间：忽略旋转输入。
- 标签页隐藏：停止旋转；恢复后从当前角度继续。
- 帧间隔异常：限制用于积分的最大时间，避免角度跳变。
- 余牌小于等于紧凑布局阈值时：保持紧凑布局静止，不应用环形旋转。
- 减少动态效果模式：仍允许直接手掌控制，但降低最大旋转速度。

## 测试设计

### 纯函数测试

- 相同牌组和相同相位产生完全相同的布局。
- 时间变化本身不再改变布局。
- 不同显式相位产生预期方向的旋转。
- 空牌组和紧凑牌组保持有限坐标。

### 场景测试

- 旋转输入为 `0` 时，多帧后牌阵角度不变。
- 正负水平输入产生相反方向的角度变化。
- 输入停止后下一帧不再改变角度。
- 暂停和恢复期间不累积跳变。
- 抓牌后旋转输入被冻结。

### 应用集成测试

- `OPEN` 加水平移动向场景发送旋转输入。
- `PINCH`、`FIST`、`LOST` 和摄像头错误发送停止输入。
- 鼠标/触摸浏览与手势浏览共用旋转接口。
- 抽牌、正逆位、牌义、粒子归档、历史和余牌逻辑不回归。
