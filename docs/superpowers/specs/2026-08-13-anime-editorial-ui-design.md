# Anime.js 神谕编辑风 UI 优化设计

## 目标

借鉴 Anime.js 官网的强视觉层级、时间轴编排、错峰动画和精细交互反馈，将 Ether Tarot 优化为“暗色塔罗 × 鲜艳几何”的神谕编辑风体验。此次只优化界面、布局和 DOM 动效，保持现有 Three.js 场景、手势识别、卡牌数据与抽牌规则不变。

## 视觉方向

采用已确认的 A「神谕编辑风」：成熟、克制、具有精品互动作品质感。

- 延续暗色塔罗背景，以紫罗兰、薄荷青和少量玫红作为高饱和点缀。
- 使用小号章节编号、醒目衬线标题和简短操作提示建立编辑式层级。
- 3D 卡牌是绝对视觉中心；DOM 装饰限于细线轨道、刻度、状态标签与局部光晕。
- 顶部控制区重塑为纤细的“神谕控制台”，降低厚重面板感。
- 结果区按牌名、正逆位、基础牌义、AI 星语、操作入口排列。
- 历史记录使用紧凑纵向索引，不与当前结果争夺注意力。
- 小屏幕采用上下布局，控制区和结果区不得遮挡核心抽牌区域。

## 动画强度与原则

动画强度为中等且克制：明显提升质感，但不降低操作效率。

- 页面启动时，章节编号、主标题、操作提示和控制台在约 `700–1000ms` 内错峰入场；3D 场景独立启动，不等待 DOM 动画。
- 控件悬停使用边框扫光、轻微位移和颜色过渡；点击反馈约 `180ms`。
- 模式、手势和剩余牌数变化时只动画变化值，状态面板本身保持稳定。
- 抽牌开始时降低外围 DOM 信息亮度，将注意力集中到 Three.js 卡牌。
- 翻牌完成后通过一个 timeline 依次展示牌名、正逆位、基础牌义与 AI 区域。
- 新历史记录从边缘轻微滑入，并短暂高亮最新记录。
- AI 加载使用文字呼吸和细线扫描；成功、失败与重试通过短动画明确状态，不使用大面积加载特效。
- 动画优先使用 `transform`、`opacity` 和 CSS 变量，避免频繁布局计算。

## 技术结构

### Anime.js 集成

- 在 `package.json` 中加入当前稳定的 Anime.js 依赖，并提交锁文件变化。
- 浏览器从项目本地路径加载 Anime.js ESM 构建；Node 静态服务器需显式、安全地映射该依赖文件，不开放整个 `node_modules`。
- 不依赖运行时 CDN，避免网络或 CSP 变化使动画影响核心体验。

### UI 动画模块

新建 `src/client/ui-motion.js`，它只操作 DOM，不导入或接触 Three.js 对象。模块对外提供：

- `createUiMotion(options)`：创建带有元素查询、减少动态效果检测和 Anime.js 适配器的控制器。
- `intro()`：执行首屏错峰入场。
- `updateStatus(element, value)`：更新并动画单个状态值。
- `focusReading()` / `releaseReading()`：降低或恢复外围 UI 的视觉权重。
- `revealResult()`：按确认顺序揭示结果内容。
- `revealHistory(entry)`：为新历史项提供滑入和短暂高亮。
- `setAiState(state)`：处理 `loading`、`success`、`error` 与 `idle` 的 DOM 动效。
- `destroy()`：取消在途动画并解除媒体查询或页面可见性监听。

接口可以使用一个控制器对象承载上述方法；具体导出形式以实施计划为准，但行为与边界必须保持一致。

### 现有页面接入

- `index.html` 调整 DOM 分组、语义标签和样式，保留现有脚本依赖的 ID。
- 现有抽牌流程只在明确状态节点调用 UI 动画接口，不改变卡牌选择、翻转、正逆位、历史数据或 AI 请求逻辑。
- 页面隐藏时暂停非必要循环 DOM 动画；恢复可见时仅恢复仍然有效的状态动画。
- 快速重复操作时，开始新动画前取消或覆盖同一目标上的旧动画，防止 timeline 竞争样式。

## 响应式与无障碍

- 使用 CSS 媒体查询保证桌面与窄屏布局均不遮挡 3D 抽牌区域。
- 尊重 `prefers-reduced-motion: reduce`。减少动态效果下关闭位移、缩放、错峰和循环，只保留极短透明度变化或直接设置最终状态。
- 动画不能改变焦点顺序、按钮可点击性、`aria-live` 行为或文本可读性。
- 颜色对比不能只依赖霓虹光晕；状态仍需通过文字表达。

## 降级与错误处理

- Anime.js 模块加载失败时，页面仍显示最终布局并完整支持抽牌、结果、历史与 AI 解读。
- 任一预期 DOM 元素缺失时，对应动画无操作，不抛出阻断主流程的异常。
- 动画取消后必须留下明确的最终视觉状态，不允许内容停留在透明或不可交互状态。
- 低性能设备不增加新的持续粒子层；DOM 循环动画数量保持最少。

## 测试与验收

### 自动化测试

- 首屏初始化会将目标元素带到最终可见状态。
- 减少动态效果模式跳过位移、缩放、错峰和循环动画。
- 结果揭示顺序为牌名与方向、基础牌义、AI 区域。
- 同一目标的新动画会取消或覆盖旧动画。
- 缺失元素和动画适配器不可用时安全降级。
- UI 动画模块不接触 Three.js 对象或改变抽牌状态。
- 现有 `npm test` 测试集继续全部通过。

### 视觉验收

- 桌面首屏具有明确的编辑式标题与单一中心焦点。
- 控制区、结果区和历史区在桌面与窄屏均不遮挡关键卡牌交互。
- 动画结束后文本清晰、控件可用、状态准确。
- 减少动态效果模式下，完整流程可用且没有持续动画。

## 非目标

- 不修改 Three.js 摄像机、灯光、材质、卡牌运镜或渲染循环。
- 不修改 MediaPipe 手势判定与鼠标备用操作规则。
- 不重构卡牌数据、AI 服务端接口或抽牌业务状态。
- 不照搬 Anime.js 官网品牌、文案或具体动画作品。
