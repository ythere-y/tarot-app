# 本地快捷启动脚本设计

## 目标

在 Windows PowerShell 中通过一个项目内脚本启动 Ether Tarot。脚本读取项目根目录 `.env` 中的 `PORT`，自动结束正在监听该端口的进程，然后在当前终端运行 `npm start`。

## 入口与使用方式

- 文件名：`start-local.ps1`
- 从任意当前目录调用时，脚本都以自身所在目录作为项目根目录。
- 常规调用：`./start-local.ps1`
- 若 PowerShell 执行策略阻止本地脚本，可使用：`powershell -ExecutionPolicy Bypass -File ./start-local.ps1`

## 配置解析

脚本读取项目根目录的 `.env`，查找最后一个有效的 `PORT` 配置。

- 接受 `PORT=8090`、`PORT = 8090`、单引号或双引号包裹的数字。
- 忽略空行、整行注释和行尾注释。
- `.env` 不存在或未设置 `PORT` 时，使用服务器默认端口 `8090`。
- 端口必须是 `1` 到 `65535` 的整数；无效值会输出错误并停止，不会结束任何进程。

## 启动流程

1. 确认 `node` 和 `npm` 命令可用。
2. 解析并验证端口。
3. 查询所有监听目标端口的 TCP 连接。
4. 对每个唯一 PID 显示进程名称和 PID，并使用 `Stop-Process -Force` 自动结束。
5. 等待端口释放；若在限定时间内仍被占用，输出错误并停止。
6. 切换到项目根目录，在当前终端执行 `npm start`。

`npm start` 保持前台运行，以便用户看到日志并通过 `Ctrl+C` 停止服务。

## 安全与错误处理

- 这是用户明确选择的无确认模式，目标端口上的任何监听进程都会被强制结束。
- 仅操作解析出的单个 TCP 端口，不按进程名称批量结束。
- 若无法读取进程名称，仍显示 PID 并尝试结束。
- 权限不足、进程无法结束、端口未释放或 `npm start` 失败时，脚本返回非零退出码并给出明确提示。

## 验证

自动化测试覆盖：默认端口、常见 `.env` 格式、无效端口，以及脚本关键启动行为。手动验证使用一个临时监听进程占用测试端口，确认脚本结束该进程并成功启动服务器，同时避免触碰用户当前的 `8090` 服务。
