# CHATAROT 风格洗牌体验设计

## 目标

在保留 Ether Tarot 品牌、牌面、手势抽牌和 AI 星语的前提下，吸收 CHATAROT.AI 的黑金深空视觉语言，并独立实现一套同等节奏的 78 张牌三维洗牌编排。现有代码只有一张厚牌堆网格和 78 个逻辑牌 ID，因此实现会由逻辑牌组生成 78 张轻量卡背网格。用户主动点击“开始洗牌”后，牌组依次经历收束、球状散开、旋转、切牌和合拢，完成后才进入可抽牌状态。

参考体验：

- `https://chatarot.ai/`
- `https://www.allenluuu.com/random-tarot/spreads/daily/linear`

本项目不复制参考站代码、商标、文案、卡背或其他品牌素材；仅借鉴可观察的交互结构、动画节奏和视觉层级。

## 范围

本次包含：

- 根据现有 78 个逻辑牌 ID 创建轻量 Three.js 卡背网格，并完成完整洗牌序列。
- 主动“开始洗牌”、跳过动画和洗牌完成状态。
- 洗牌期间的输入锁定及完成后的新手引导衔接。
- 黑金深空配色、中央仪式舞台、精简状态信息和底部控制区。
- 减少动态效果降级、窗口变化与中断恢复。

本次不包含：

- 自由文本提问、付费次数、账户、牌阵选择或聊天功能。
- 复制参考站牌背、粒子素材、Logo、源码或精确文案。
- 修改抽牌随机规则、正逆位概率、牌义和 AI 接口。

## 用户流程

1. 首次用户完成输入模式和解读主题选择；返回用户直接进入牌桌。
2. 中央牌组处于不可抽取状态，并显示“开始洗牌”主按钮。
3. 用户点击按钮后，界面锁定抽牌输入并播放完整洗牌序列。
4. 用户可以选择“跳过动画”，控制器立即把所有卡牌安全归位。
5. 洗牌完成后显示短暂“洗牌完成”反馈，输入解锁，新手引导继续提示抓牌。
6. 尚未抓牌且未展示结果时，用户可以主动“重新洗牌”。

## 动画编排

### 阶段 1：Converge / 收束

- 星空粒子视觉速度提高并向中央聚焦。
- 78 张牌从当前牌堆位置压紧为规整中央牌组。
- 持续约 600ms，使用平滑的缓入缓出曲线。

### 阶段 2：Sphere / 球状散开

- 使用 Fibonacci sphere 为 78 张牌生成近似均匀的球面目标点。
- 卡牌按短错峰从中央飞向球面，牌背保持朝向观看者或球体外侧。
- 球体半径根据视口和设备能力限制，避免移动端越界。

### 阶段 3：Orbit / 旋转洗牌

- 牌组整体完成两轮加速再减速的空间旋转。
- 单张牌叠加轻微、确定性的旋转偏移，使层次自然但可重复测试。
- 星空粒子同步加速，强调能量汇聚，但不遮挡牌组。

### 阶段 4：Cut / 切牌

- 牌组按索引奇偶或洗牌顺序分为左右两叠。
- 两叠在水平方向拉开并形成短暂停顿，让“切牌”动作清晰可读。
- 左右牌堆保持轻微相反倾角。

### 阶段 5：Merge / 合拢

- 两叠牌按交错顺序逐张回到中央。
- 每张牌使用极短错峰，形成类似桥式洗牌后的压合节奏。
- 最终坐标、旋转和层级恢复到可抽取牌堆的标准状态。

### 阶段 6：Ready / 就绪

- 星空恢复常速。
- 输入锁定解除。
- 按钮变为“重新洗牌”，阶段提示变为“牌已就绪”。
- 首次引导接续当前模式的“移向牌堆”步骤。

## 视觉设计

- 背景改为近黑色深空，粒子使用灰白与少量暖金，不使用大面积彩色光晕。
- 主要边框和状态强调使用低饱和暖金；正文使用温暖灰白。
- 品牌区缩小，中央牌组和当前动作成为首要层级。
- 洗牌状态文字位于牌组上方，使用小号大字距英文标签配中文说明。
- “开始洗牌”是舞台唯一高强调按钮；模式、主题、帮助和记录收纳到较低层级控制区。
- 保留 Ether Tarot 名称和自身视觉辨识度，不复刻 CHATAROT.AI 的导航、角标或排版比例。

## 技术结构

新增 `src/client/shuffle-sequence.js`，负责可测试的动画状态与目标计算；`index.html` 以共享几何体和材质创建 78 张轻量卡背网格，避免为每张牌重复分配资源：

- `createShuffleSequence({ cardCount, reducedMotion })`
- `start(cards)`
- `update(deltaSeconds)`
- `skip()`
- `reset()`
- `getState()`
- `onComplete(callback)`

状态依次为：

`idle -> converge -> sphere -> orbit -> cut -> merge -> ready`

控制器不创建渲染器、不读取 DOM、不处理手势，只更新传入卡牌对象的位置和旋转。目标位置生成、阶段推进和缓动函数保持确定性，便于单元测试。

`index.html` 负责：

- 显示洗牌按钮、阶段说明和跳过动作。
- 把洗牌状态接入现有 `STATE.locked` 与新手引导。
- 在渲染循环中调用 `shuffleSequence.update(dt)`。
- 洗牌期间阻止 `createHeldCard()` 和确认操作。
- 在窗口变化、模式切换或跳过时保持卡牌可恢复。

## 与现有引导衔接

- 新手引导在主题选择后进入 `shuffle` 步骤，而不是直接进入 `target-deck`。
- 点击开始洗牌后，引导提示当前动画阶段但不要求额外操作。
- `shuffle-complete` 事件将引导推进到对应输入模式的第一个实际操作步骤。
- 返回用户同样需要主动洗牌，但不重复首次模式与主题弹窗。
- “操作帮助”重播时，如果本轮牌组尚未就绪，先提示完成洗牌；若已经就绪，直接从抓牌教学开始。

## 中断、异常与性能

- 洗牌期间忽略抓牌、揭示和再次开始洗牌请求。
- 跳过会把全部卡牌一次性恢复到标准牌堆，并只触发一次完成事件。
- 页面失焦或帧率下降不会依赖帧数推进，所有阶段使用累计时间。
- 窗口尺寸变化只影响下一次洗牌的球体半径；当前序列不突然跳位。
- `prefers-reduced-motion: reduce` 下使用约 600ms 的收束和合拢，不执行高速球状旋转。
- 设备性能不足时降低粒子数量，但仍使用 78 张真实牌完成位置编排。

## 验收标准

1. 用户必须主动点击“开始洗牌”，完成前不能抓牌。
2. 78 张真实卡牌依次完成收束、球状散开、两轮旋转、左右切牌、交错合拢与就绪。
3. 完整序列结束后卡牌均恢复到可抽取的标准牌堆位置。
4. 洗牌期间所有手势和鼠标抽牌输入被锁定。
5. 跳过动画、减少动态效果和重复洗牌都不会导致卡牌散落或重复完成事件。
6. 首次引导在洗牌完成后自然衔接到当前输入模式的抓牌步骤。
7. 桌面和窄屏都能看到完整牌组、阶段信息和操作按钮。
8. 原有抽牌随机、正逆位、历史记录、AI 解读和元素特效继续工作。

## 测试策略

- 单元测试覆盖阶段顺序、78 个球面目标、两轮旋转、切牌分组、交错合拢、跳过、重置和减少动态效果。
- 新手引导测试覆盖新增 `shuffle` 与 `shuffle-complete` 事件。
- 页面烟雾测试覆盖洗牌按钮、阶段区域、跳过按钮、控制器接线和减少动态效果。
- 完整 `npm test` 回归。
- 真实浏览器验证首次鼠标流程、重复洗牌、窄屏布局和减少动态效果；手势路径验证洗牌期间不可抓牌及完成后解锁。
